# Deploying: API on Render, website on Vercel, database on MongoDB Atlas

```
Browser ──► Vercel (website, apps/web) ──/api/v1/*──► Render (API, apps/api) ──► MongoDB Atlas
                                                       ▲
                    cash-desk program / printer agent ─┘ (through the website address, or directly)
```

The website forwards every `/api/v1/...` request to the API, so the browser only ever talks to the
Vercel address and the login cookie stays first-party. The API creates its database, indexes and the
platform owner (`admin`) by itself on the first start: there is no console step.

Everything below is done in **your** accounts (GitHub, MongoDB Atlas, Render, Vercel). Secrets (the
database address, the admin password) are typed only into those dashboards, never into a file.

---

## 1. Put the code on GitHub

1. On github.com: **New repository** → name it (e.g. `online-kass`) → **Private** → do **not** add a README → **Create**.
2. In the project folder (the commit was already made for you, or run `git add -A` and `git commit -m "Online Kass"` first):

```bash
git branch -M main
git remote add origin https://github.com/<your-user>/online-kass.git
git push -u origin main
```

`.env` and `.devdata/` are git-ignored, so no secrets or local data are pushed.

## 2. MongoDB Atlas: let Render connect

1. Atlas → your project → **Network Access** → **Add IP Address** → **Allow access from anywhere** (`0.0.0.0/0`) → Confirm.
   (Render's free plan has no fixed IP address; the database is still protected by its user and password.)
2. **Database Access**: the user `leetcoder24` needs **Read and write to any database** (the default for a new user).
3. Because the connection string was shared in a chat, change this user's password now
   (Database Access → Edit → Edit Password) and use the new password in step 3.

The connection string to use: `mongodb+srv://leetcoder24:<password>@cluster0.5rxtcei.mongodb.net/`
(a string without a database name is fine: the API uses the database `onlinekass`).

## 3. Render: the API

1. render.com → **New +** → **Blueprint** → connect GitHub → pick the repository.
   Render reads `render.yaml` from the repository and shows the service `online-kass-api`.
2. It asks for the values marked secret:
   | Key | Value |
   | --- | --- |
   | `MONGO_URI` | the Atlas connection string from step 2 |
   | `WEB_ORIGIN` | for now `https://example.vercel.app`; you replace it in step 5 |
   | `SUPERADMIN_PASSWORD` | `a@a@admina@a@` (or a new one: this is the platform owner's password) |
3. **Apply**. The first build takes 3–5 minutes.
4. Open `https://<your-service>.onrender.com/api/v1/health`. It must show `"status":"ok"` and `"db":true`.
   If it does not, open the service → **Logs** (a wrong password or a missing Atlas network rule shows there).

Copy the service address (e.g. `https://online-kass-api.onrender.com`). JWT secrets and the encryption
key were generated by Render; do not change them later (changing `ENCRYPTION_KEY` makes stored fiscal
credentials and agent pairings unreadable).

## 4. Vercel: the website

1. vercel.com → **Add New…** → **Project** → import the GitHub repository.
2. **Root Directory**: `apps/web` (Edit → choose `apps/web`). Framework: **Next.js** (detected).
3. **Environment Variables**: `API_URL` = the Render address from step 3 (e.g. `https://online-kass-api.onrender.com`).
   Do not add `NODE_ENV` here (it belongs to Render only). `apps/web/vercel.json` sets the install
   command, so leave Build / Install / Output settings on their defaults.
4. **Deploy**. When it finishes, open the website address (e.g. `https://online-kass.vercel.app`) and log in
   with `admin` / the `SUPERADMIN_PASSWORD` you set.

`API_URL` is read while the website is built: if you change it later, redeploy the website.

## 5. Tell the API the website address

Render → the service → **Environment** → `WEB_ORIGIN` = the Vercel address from step 4 (no slash at the end)
→ **Save, rebuild and deploy**.

## 6. Cash-desk program and printer agent

On the superadmin shop page → **Programs**, the server address is pre-filled with the website address
(`https://<your-site>.vercel.app/api/v1`): download the program for each register from the live site and it
connects there.

---

## Things to know

* **Render free plan sleeps** after 15 minutes without requests. The next request then takes about a
  minute (the website may show a loading state or an error once, then works), and background jobs
  (scheduled price changes, Telegram daily reports, webhook retries) pause while it sleeps. For a shop
  that sells every day, switch the service to the **Starter** plan (Render → service → Settings → Instance Type).
* **Uploaded images** (product photos, receipt logos) are stored on the API server's disk, which Render
  clears on every deploy. Re-upload them after a deploy, or use a paid plan with a persistent disk.
* **Atlas free tier (M0)** has a 512 MB limit: enough for tens of thousands of sales.
* Health check: `https://<render-address>/api/v1/health`. API docs: `https://<render-address>/api/v1/docs`.
